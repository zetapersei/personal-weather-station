# Personal Weather Station

A small Raspberry Pi weather station that reads environmental data from 1-Wire and DHT sensors, stores time-series values in RRD databases, and exposes HTML/CGI graphs through a web interface.

## Overview

This project gathers temperature and humidity data from a DS18B20 probe and a DHT11 sensor, updates round-robin databases, and visualizes the trend over day, week, month, and year ranges through lightweight CGI scripts served by a web server.

The repository contains:

- `gettemp.py` — reads the DS18B20 temperature sensor and stores values in the temperature RRD database and MySQL table.
- `gethum.py` — reads the DHT sensor and stores humidity values in the humidity RRD database and MySQL table.
- `create_db_temp.sh` and `create_db_hum.sh` — initialize the RRD archives.
- `crontab.example` — example schedule for running both collectors every five minutes.
- `www/graph_temp.pl` and `www/graph_hum.pl` — generate PNG graphs from the RRD files.
- `www/index.html` — dashboard page that displays the graphs and lets the user pick the time window.

## Hardware

- Raspberry Pi
- DS18B20 temperature sensor
- DHT11/DHT22 sensor
- 4.7 kΩ pull-up resistor for the DS18B20 bus (when required by the wiring)

## Software requirements

On the Raspberry Pi, install:

```bash
sudo apt-get update
sudo apt-get install lighttpd rrdtool librrds-perl python3-rrdtool python3-pip
```

For Python dependencies:

```bash
sudo pip3 install Adafruit_DHT mysqlclient
```

If you use the MySQL/MariaDB integration, make sure the database and table structures already exist, for example:

```sql
CREATE DATABASE weather;
CREATE TABLE wr_temperature (
    id INT AUTO_INCREMENT PRIMARY KEY,
    sensor_id INT NOT NULL,
    value DECIMAL(6,3) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE wr_humidity (
    id INT AUTO_INCREMENT PRIMARY KEY,
    sensor_id INT NOT NULL,
    value DECIMAL(6,3) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 1-Wire configuration

Enable the 1-Wire interface in `/boot/config.txt`:

```text
dtoverlay=w1-gpio
```

Add the kernel modules in `/etc/modules`:

```text
w1-gpio pullup=1
w1-therm
```

Reboot the Raspberry Pi after updating the configuration.

## Web server configuration

Enable CGI support:

```bash
sudo lighty-enable-mod cgi
sudo lighty-enable-mod userdir
```

Update `/etc/lighttpd/conf-enabled/10-cgi.conf` so CGI scripts are executed correctly:

```text
cgi.assign = (
    ".pl" => "/usr/bin/perl",
    ".py" => "/usr/bin/python3",
)
```

Then restart Lighttpd:

```bash
sudo systemctl restart lighttpd
```

## Database initialization

Create the RRD files:

```bash
./create_db_temp.sh
./create_db_hum.sh
```

These scripts create the files at `/home/pi/personal-weather-station/temperature.rrd` and `/home/pi/personal-weather-station/humidity.rrd` by default. You can override the target path with the `RRD_PATH` environment variable.

## Usage

Run the data collection scripts manually:

```bash
python3 /home/pi/personal-weather-station/gettemp.py
python3 /home/pi/personal-weather-station/gethum.py
```

To schedule both scripts every five minutes, first check that the paths and Python executable in [`crontab.example`](./crontab.example) match your installation. The example assumes the project is installed at `/home/pi/personal-weather-station` and that the jobs run as the `pi` user. Install the entries with:

```bash
crontab -e
```

Copy the two active schedule lines from `crontab.example` into the editor and save. This preserves any other existing cron jobs. The scripts' output is sent to the system log with distinct tags; view recent messages with:

```bash
sudo journalctl -t weather-station-temperature -t weather-station-humidity
```

The dashboard is available from the web server at:

```text
http://<raspberry-pi-ip>/~pi/
```

If you expose the project via a different web root, point the browser to the `www` directory generated by this project.

## Notes

- The scripts are designed for a Raspberry Pi environment and assume the sensor files and RRD database paths are present at fixed locations.
- The code has been updated to be compatible with Python 3 and to handle missing sensor, database, or RRD errors more safely than the original version.
- The sample cron schedule runs both collectors every five minutes; ensure the cron user can access the sensor and RRD files.
